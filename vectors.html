5  Vectors

There are seven vector types in R:

  • Logical (LGLSXP), contains Rboolean.

  • Integer (INTSXP), contains int.

  • Double (REALSXP), contains double.

  • Complex (CPLXSXP), contains Rcomplex.

  • String (STRSXP), contains CHARSXP.

  • Lists (VECSXP), contains any other sexp. Beware: Lists are VECSXPs not LISTSXPs. This is because early implementations of lists were Lisp-like linked lists, which are now called as “pairlists”.

  • Raw (RAWSXP), contains Rbyte.

  • Expression (EXPRSXP), contains LANGSXP, SYMSXP or a vector (except for a list).

Three of those vectors are built on top of simple types defined by R:

typedef unsigned char Rbyte;

typedef enum { 
  FALSE = 0, 
  TRUE 
} Rboolean;

typedef struct {
  double r;
  double i;
} Rcomplex;

5.1 Length

5.1.1 Rf_xlength() (Rf_length())

Get the length of a vector.

R_xlen_t Rf_xlength(SEXP x);
R_len_t Rf_length(SEXP x);

Status: API · Header: Rinternals.h · Protect: not needed · Errors: never · Since: — · R equivalent: length()

  • x: any vector.

Historically, R vectors were limited to length 2^31 - 1, and most vectors are still shorter than this, so the int-based Rf_length() interface suffices. As of R 3.0.0, vectors can have length up to 2^64 - 1; use the R_xlen_t-based Rf_xlength() if you want your code to be as general as possible. Also works on pairlists, where it is O(n).

See also: Rf_lengthgets(), LENGTH()

5.1.2 Rf_lengthgets() (Rf_xlengthgets())

Set the length of a vector by creating a new vector of extended length.

SEXP Rf_lengthgets(SEXP x, R_len_t n);
SEXP Rf_xlengthgets(SEXP x, R_xlen_t n);

Status: API · Header: Rinternals.h · Protect: result · Errors: can throw · Since: — · R equivalent: length<-

  • x: a vector.
  • n: the new length.

Sets the length of a vector by creating a new vector of extended length. Rf_xlengthgets() is the R_xlen_t-based variant for long vectors (available since R 3.0.0).

See also: Rf_xlength(), SETLENGTH()

5.1.3 LENGTH() (XLENGTH())

Get the length of a vector.

int LENGTH(SEXP x);
R_xlen_t XLENGTH(SEXP x);

Status: API · Header: Rinternals.h · Protect: n/a · Errors: never · Since: — · R equivalent: length()

  • x: any vector.

Uppercase variants of Rf_length()/Rf_xlength(); in base R code these are implemented as macros for efficiency.

See also: Rf_xlength(), SETLENGTH()

5.1.4 SETLENGTH()

Set the length of a vector in place.

void SETLENGTH(SEXP x, int v);

Status: non-API (use Rf_lengthgets()) · Header: Rinternals.h · Protect: n/a · Errors: never · Since: — · R equivalent: length<-

  • x: a vector.
  • v: the new length.

Uppercase variant of Rf_lengthgets(); in base R code these uppercase variants are implemented as macros for efficiency. For resizable (growable) vectors, R 4.6.0 adds R_resizeVector(); see R_allocResizableVector().

See also: Rf_lengthgets(), LENGTH()

5.1.5 IS_LONG_VEC()

Test whether a vector is a long vector.

int IS_LONG_VEC(SEXP x);

Status: API · Header: Rinternals.h · Protect: n/a · Errors: never · Since: R 3.0.0 · R equivalent: —

  • x: any vector.

As of R 3.0.0, R vectors can have length up to 2^64 - 1; a long vector is one whose length exceeds the int-based limit of 2^31 - 1.

See also: Rf_xlength()

After the SEXPTYPE, the most important property of a vector is it’s length. Historically, R vectors were limited to length \(2 ^ {31} - 1\). Still most vectors are shorter than this, so you can use an int based interface:

typedef int R_len_t;

As of R 3.0.0, R vectors can have length up to \(2 ^ {64} - 1\). If you want your code to be as general as possible, you should instead use the R_xlen_tbased interface:

// ptrdiff_t is the type of the result of subtracting two pointers, and
// is usually 8 bytes (like a double)
typedef ptrdiff_t R_xlen_t;

These functions also have uppercase variants - in base R code these are implemented as macros for efficiency.

5.2 Create

5.2.1 Rf_allocVector()

Create a new vector of the given type and length.

SEXP Rf_allocVector(SEXPTYPE type, R_xlen_t n);

Status: API · Header: Rinternals.h · Protect: result · Errors: can throw · Since: — · R equivalent: vector()

  • type: any vector SEXPTYPE (LGLSXP, INTSXP, REALSXP, CPLXSXP, STRSXP, VECSXP, RAWSXP, EXPRSXP).
  • n: number of elements; R_xlen_t supports long vectors on 64-bit platforms.

The most common way to create a new vector. Atomic vector contents are uninitialised; VECSXP/EXPRSXP elements are R_NilValue and STRSXP elements are "". Attributes are unset.

SEXP out = PROTECT(Rf_allocVector(REALSXP, n));

See also: Rf_allocVector3(), Rf_coerceVector()

5.2.2 Rf_ScalarLogical() (Rf_ScalarInteger(), Rf_ScalarReal(), Rf_ScalarComplex(), Rf_ScalarRaw())

Create a vector of length 1 from the corresponding C type.

SEXP Rf_ScalarLogical(int x);
SEXP Rf_ScalarInteger(int x);
SEXP Rf_ScalarReal(double x);
SEXP Rf_ScalarComplex(Rcomplex x);
SEXP Rf_ScalarRaw(Rbyte x);

Status: API · Header: Rinternals.h · Protect: result · Errors: can throw · Since: — · R equivalent: —

  • x: the C value to wrap.

As with all SEXP creation functions you must PROTECT() the result of any of these calls unless you’re immediately assigning it into an already protected object. For strings see Rf_ScalarString() and Rf_mkString().

See also: Rf_allocVector(), Rf_ScalarString(), Rf_mkString()

5.2.3 Rf_coerceVector()

Coerce an existing vector to a different type.

SEXP Rf_coerceVector(SEXP x, SEXPTYPE newtype);

Status: API · Header: Rinternals.h · Protect: result · Errors: can throw · Since: — · R equivalent: as.vector()

  • x: a vector.
  • newtype: the SEXPTYPE to coerce to.

Errors if it can’t coerce between TYPEOF(x) and newtype.

See also: Rf_allocVector(), Rf_asLogical()

5.2.4 Rf_mkNamed()

Create a named vector of the given type.

SEXP Rf_mkNamed(SEXPTYPE type, const char **names);

Status: API · Header: Rinternals.h · Protect: result · Errors: can throw · Since: — · R equivalent: setNames()

  • type: any vector SEXPTYPE.
  • names: a null-terminated array of const char* names.

Given a null-terminated array of const char*s, creates a vector of that length and initialises a character vector of names.

// array of names; note the null string
const char *names[] = {"xname", "yname", ""};
SEXP list = PROTECT(Rf_mkNamed(VECSXP, names));  // creates a list of length 2
SET_VECTOR_ELT(list, 0, x); // x and y are arbitrary SEXPs
SET_VECTOR_ELT(list, 1, y);
UNPROTECT(1);

See also: Rf_allocVector()

5.2.5 Rf_allocVector3()

Create a new vector using a custom allocator.

SEXP Rf_allocVector3(SEXPTYPE type, R_xlen_t n, R_allocator_t *allocator);

Status: API · Header: Rinternals.h · Protect: result · Errors: can throw · Since: R 3.4.0 · R equivalent: —

Like Rf_allocVector(), but memory for the data payload comes from allocator. Pass NULL to get exactly Rf_allocVector() behaviour. Rarely needed in package code.

See also: Rf_allocVector()

The most common way to create a new vector is with Rf_allocVector(). If you want to create a vector of length 1 from the corresponding C type, use the scalar helpers.

(Note, as with all SEXP creation functions you must Rf_protect() the result of any of these calls unless you’re immediately assigning it into an already protected object)

Alternatively you can coerce from an existing vector with Rf_coerceVector().

To create a named vector, use Rf_mkNamed().

For example, this template creates a list holding two objects x and y named xname and yname:

  // array of names; note the null string
  const char *names[] = {"xname", "yname", ""};
  SEXP list = PROTECT(Rf_mkNamed(VECSXP, names));  // creates a list of length 2
  SET_VECTOR_ELT(list, 0, x); // x and y are arbitrary SEXPs
  SET_VECTOR_ELT(list, 1, y);
  UNPROTECT(1);

Finally, you can use a custom allocator:

// Create a vector with a custom memory allocator
typedef void *(*custom_alloc_t)(R_allocator_t *allocator, size_t);
typedef void  (*custom_free_t)(R_allocator_t *allocator, void *);
typedef struct R_allocator {
    custom_alloc_t mem_alloc; /* malloc equivalent */
    custom_free_t  mem_free;  /* free equivalent */
    void *res;                /* reserved (maybe for copy) - must be NULL */
    void *data;               /* custom data for the allocator implementation */
} R_allocator_t;

5.3 Get and set values

5.3.1 LOGICAL() (INTEGER(), REAL(), COMPLEX(), RAW())

Get a pointer to the underlying C array of an atomic vector.

int*      LOGICAL(SEXP x);
int*      INTEGER(SEXP x);
double*   REAL(SEXP x);
Rcomplex* COMPLEX(SEXP x);
Rbyte*    RAW(SEXP x);

Status: API · Header: Rinternals.h · Protect: not needed · Errors: never · Since: — · R equivalent: —

  • x: a vector of the corresponding type.

These functions are all upper case and don’t start with Rf_. When working with longer vectors, there’s typically a performance advantage to saving the pointer and reusing it rather than calling the accessor on every iteration.

int* px = INTEGER(x);
for (int i = 0; i < n; ++i) {
  px[i] = px[i] * 2;
}

See also: STRING_ELT(), VECTOR_ELT()

5.3.2 STRING_ELT() (SET_STRING_ELT())

Get or set a single element of a character vector.

SEXP STRING_ELT(SEXP x, R_xlen_t i);
void SET_STRING_ELT(SEXP x, R_xlen_t i, SEXP v);

Status: API · Header: Rinternals.h · Protect: not needed · Errors: can throw · Since: — · R equivalent: —

  • x: a STRSXP.
  • i: zero-based element index.
  • v: the CHARSXP to set.

STRING_ELT() returns a CHARSXP. Strings don’t map to simple C structs, so they use a pair of functions to get and set values.

See also: VECTOR_ELT(), STRING_PTR()

5.3.3 VECTOR_ELT() (SET_VECTOR_ELT())

Get or set a single element of a list.

SEXP VECTOR_ELT(SEXP x, R_xlen_t i);
SEXP SET_VECTOR_ELT(SEXP x, R_xlen_t i, SEXP v);

Status: API · Header: Rinternals.h · Protect: not needed · Errors: can throw · Since: — · R equivalent: —

  • x: a VECSXP.
  • i: zero-based element index.
  • v: the value to set.

VECTOR_ELT() returns potentially any SEXPTYPE. Lists don’t map to simple C structs, so they use a pair of functions to get and set values.

See also: STRING_ELT(), VECTOR_PTR()

5.3.4 STRING_PTR()

Get a pointer to the elements of a character vector.

SEXP* STRING_PTR(SEXP x);

Status: non-API (use STRING_PTR_RO()) · Header: Rinternals.h · Protect: not needed · Errors: never · Since: — · R equivalent: —

  • x: a STRSXP.

Used in a handful of places in the R source. Obtaining a writable pointer to character vector data can violate the memory manager’s integrity assumptions and is not supported; use STRING_PTR_RO() instead.

See also: STRING_ELT()

5.3.5 VECTOR_PTR()

Get a pointer to the elements of a list.

SEXP* VECTOR_PTR(SEXP x);

Status: non-API (use VECTOR_ELT()) · Header: Rinternals.h · Protect: not needed · Errors: can throw · Since: — · R equivalent: —

  • x: a VECSXP.

A deprecated interface that now throws an error.

See also: VECTOR_ELT()

The simple types are wrappers around an array of C values, so you get and set by using a helper that returns a pointer:

NB: these functions are all upper case and don’t start with Rf_.

When working with longer vectors, there’s typically a performance advantage to saving the index and reusing. For example, instead of:

for (int i = 0; i < n; ++i) {
  INTEGER(x)[i] = INTEGER(x)[i] * 2;
}

Do:

int* px = INTEGER(x);
for (int i = 0; i < n; ++i) {
  px[i] = px[i] * 2;
}

Strings and lists don’t map to simple C structs, so instead have a pair of functions to get and set values.

(There is STRING_PTR() which is used in a handful of places in the R source; VECTOR_PTR() is a deprecated interface that now throws an error.)

5.3.8 Special values

5.3.9 NA_LOGICAL() (NA_INTEGER(), NA_STRING())

Sentinel values for missing logical, integer, and character elements.

#define NA_LOGICAL R_NaInt
#define NA_INTEGER R_NaInt
#define NA_STRING  R_NaString

Status: API · Header: R_ext/Arith.h · Protect: n/a · Errors: never · Since: — · R equivalent: NA

Integer, logical, and character vectors have special sentinels for missing values. NA_LOGICAL and NA_INTEGER are both R_NaInt (currently INT_MIN); NA_STRING is R_NaString.

See also: NA_REAL()

5.3.10 NA_REAL() (R_NaReal())

Missing value sentinel for doubles.

double R_NaReal;
#define NA_REAL R_NaReal

Status: API · Header: R_ext/Arith.h · Protect: n/a · Errors: never · Since: — · R equivalent: NA_real_

Missing values are somewhat more complicated for REALSXP because there is an existing protocol for missing values defined by the IEEE 754 floating-point standard. In doubles, an NA is NaN with a special bit pattern (the lowest word is 1954, the year Ross Ihaka was born).

See also: R_NaN(), ISNA(), NA_LOGICAL()

5.3.11 R_NaN() (R_PosInf(), R_NegInf())

Special floating-point values for NaN and positive and negative infinity.

double R_NaN;
double R_PosInf;
double R_NegInf;

Status: API · Header: R_ext/Arith.h · Protect: n/a · Errors: never · Since: — · R equivalent: NaN

Provided for cross-platform safety. Use these constants (and NA_REAL) to set NaN, infinite, and missing values.

See also: NA_REAL(), ISNA()

5.3.12 ISNA() (ISNAN(), R_FINITE())

Check a double for missing, NaN, or non-finite values.

int ISNA(double x);
int ISNAN(double x);
int R_FINITE(double x);

Status: API · Header: R_ext/Arith.h · Protect: n/a · Errors: never · Since: — · R equivalent: is.na()

  • x: the double to check.

Use ISNA(), ISNAN(), and !R_FINITE() to check for missing, NaN, or non-finite values. These are macros; R_IsNA(), R_IsNaN(), and R_finite() are the equivalent functions.

See also: R_IsNA(), NA_REAL()

5.3.13 R_IsNA() (R_IsNaN(), R_finite())

Check a double for missing, NaN, or non-finite values.

int R_IsNA(double);
int R_IsNaN(double);
int R_finite(double);

Status: API · Header: R_ext/Arith.h · Protect: n/a · Errors: never · Since: — · R equivalent: is.finite()

Function equivalents of the ISNA(), ISNAN(), and R_FINITE() macros. R_finite() is true when the value is not NA, NaN, Inf, or -Inf.

See also: ISNA()

Integer, logical, and character vectors have special sentinels for missing values.

Missing values are somewhat more complicated for REALSXP because there is an existing protocol for missing values defined by the floating point standard (IEEE 754). In doubles, an NA is NaN with a special bit pattern (the lowest word is 1954, the year Ross Ihaka was born), and there are other special values for positive and negative infinity. Use ISNA(), ISNAN(), and !R_FINITE() macros to check for missing, NaN, or non-finite values. Use the constants NA_REAL, R_NaN, R_PosInf, and R_NegInf to set those values.

5.4 Test

5.4.1 Rf_isLogical() (Rf_isInteger(), Rf_isReal(), Rf_isComplex(), Rf_isString(), Rf_isExpression())

Test if an SEXP is a vector of the given type.

Rboolean Rf_isLogical(SEXP s);
Rboolean Rf_isInteger(SEXP s);
Rboolean Rf_isReal(SEXP s);
Rboolean Rf_isComplex(SEXP s);
Rboolean Rf_isString(SEXP s);
Rboolean Rf_isExpression(SEXP s);

Status: API · Header: Rinternals.h · Protect: not needed · Errors: never · Since: — · R equivalent: is.logical()

  • s: any SEXP.

There’s no function to test for RAWSXP or VECSXP; you must use TYPEOF(x) == RAWSXP or TYPEOF(x) == VECSXP. (isList() tests if the object is a pairlist.) Be careful when checking whether an R object is an integer vector: internally, factors are also INTSXPs, so TYPEOF(x) == INTSXP would accept both vanilla integer vectors and factors; prefer Rf_isInteger() and Rf_isFactor() for these cases.

See also: Rf_isNewList(), Rf_isFactor()

5.4.2 Rf_isNewList() (Rf_isVectorAtomic(), Rf_isVectorList(), Rf_isVector(), Rf_isNumber(), Rf_isNumeric())

Test for frequently used combinations of vector types.

Rboolean Rf_isNewList(SEXP s);
Rboolean Rf_isVectorAtomic(SEXP s);
Rboolean Rf_isVectorList(SEXP s);
Rboolean Rf_isVector(SEXP s);
Rboolean Rf_isNumber(SEXP s);
Rboolean Rf_isNumeric(SEXP s);

Status: API · Header: Rinternals.h · Protect: not needed · Errors: never · Since: — · R equivalent: —

  • s: any SEXP.

Rf_isNewList(): NILSXP, VECSXP. Rf_isVectorAtomic(): LGLSXP, INTSXP, REALSXP, CPLXSXP, STRSXP, RAWSXP. Rf_isVectorList(): LISTSXP, EXPRSXP. Rf_isVector(): isVectorAtomic(x) || isVectorList(). Rf_isNumber(): INTSXP (but not factor), LGLSXP, REALSXP, CPLXSXP. Rf_isNumeric(): INTSXP (but not factor), REALSXP, CPLXSXP. These are not always consistent with their R equivalents: Rf_isVectorAtomic(R_NilValue) is false but is.atomic(NULL) is true, and Rf_isNewList(R_NilValue) is true but is.list(NULL) is false (somewhat strange, given that R_NilValue is just an empty pairlist, i.e. NULL and pairlist() are identical). Because of this confusion, I recommend writing your own wrapper around TYPEOF(x).

See also: Rf_isLogical()
